# Pakistan Public Health Surveillance Dashboard

## What this is

A disease-surveillance analytics dashboard built on Pakistan's NIH IDSR
weekly reporting data (2021–2026, ~421,000 records across 147 districts
and 33+ disease categories). It answers three questions a health director
actually asks: *what's happening right now, is anything unusual, and can
we trust the numbers we're looking at?*

Built from scratch in Streamlit — not a clone of the existing PowerBI
version — with eight focused pages, real statistical anomaly detection
(not just eyeballing spikes on a line chart), and a plain-language
executive summary layer sitting on top of the deeper statistics.

**Live demo:** _add your Streamlit Community Cloud link here after deploying —
see "Deploying" below, it takes about 10 minutes._

## Setup

```bash
pip install -r requirements.txt

# one-time: converts the raw Excel into fast-loading parquet files
python prepare_data.py

# run the app
streamlit run app.py
```

Open the URL Streamlit prints (usually http://localhost:8501).

## Deploying (so you can share a link instead of a zip)

1. Push this folder to a GitHub repo (public or private).
2. Go to [share.streamlit.io](https://share.streamlit.io), sign in with GitHub.
3. "New app" → pick the repo → set main file to `app.py` → Deploy.
4. Streamlit Cloud installs `requirements.txt` and runs `prepare_data.py`
   is **not** run automatically — either commit the generated
   `data/core.parquet` and `data/reporting.parquet` to the repo, or add a
   `prepare_data.py` call to a `packages.txt`/startup step.

A `Dockerfile` is also included if you'd rather deploy on any
Docker-capable host instead.

## Design philosophy: 90% plain language, 10% advanced (by choice)

Every page leads with something a non-technical reader — a director, a
DHO, a client — can understand in one glance: KPI cards that say "Rising"
instead of "CAGR +6.2%," an AI-style insight panel that writes out the
takeaway in a sentence, and captions under every chart explaining what
it means. The genuinely advanced material (correlation matrices,
Herfindahl concentration index, z-score outlier detection, Pareto
analysis) is still fully there — on the Executive Analytics page it's
folded into a single **"🔬 Advanced statistics"** expander so it doesn't
compete with the plain-language summary for attention, and on Outbreak
Alerts the WHO-style endemic-channel comparison is the same way. Nothing
was removed; it's just opt-in rather than in the way.

## What's genuinely new vs. the PowerBI version

- **Outbreak alerts**: rolling-mean + N-std control limits (Shewhart-style)
  plus an EWMA overlay and a WHO-style calendar-week endemic channel —
  not just eyeballing spikes.
- **Executive Analytics**: CAGR, volatility (CV), disease concentration
  (HHI), Pareto (80/20) analysis, year-over-year growth heatmap, and
  z-score outlier detection — none of which exist in the PowerBI file.
- **Population-adjusted rates**: Geography's province share chart can
  toggle between raw case counts and **cases per 100,000 people**, using
  2023 census province populations, so a large province isn't
  automatically read as "worse" than a small one just because it has
  more people.
- **Geography**: an actual bubble map plus a province rank-over-time
  (bump chart) and a category-profile radar — not just ranked bars.
- **Seasonality**: calendar heatmap, streamgraph, and year-over-year
  comparison — nothing in the PowerBI file shows recurring patterns.
- **Forecast**: lightweight 4-week trend projection per top disease.
- **Reporting quality**: built from the `IDSR reporting districts` sheet,
  which the PowerBI dashboard never touches at all.
- **Shared slicers**: province / category / disease / date filters persist
  across all eight pages via `st.session_state`.

## Honest limitations (what I'd do next with more time)

- **Population adjustment is province-level only.** District-level
  populations for all 147 districts aren't included because I don't have
  a verified source for them — adding a real district population table
  would let per-district rates replace the raw bubble-map sizing too.
- **The map uses curated district centroids, not a real choropleth.**
  Swap in a full Pakistan district GeoJSON to shade actual district
  boundaries instead of bubbles.
- **The forecast is intentionally a simple trend-blended projection**,
  not Prophet/SARIMAX — good enough to flag direction, not for
  production-grade forecasting.
- **No authentication.** Fine for a portfolio/demo deployment; would need
  basic auth or SSO before being genuinely public-facing with real
  provincial data.
- **No automated tests yet.** The statistical logic (control limits,
  HHI, z-scores, CAGR) was manually verified against known formulas and
  checked with Streamlit's `AppTest` framework across all 8 pages under
  multiple filter combinations, but a small `pytest` suite on
  `utils/anomaly.py` and `utils/data_loader.py` would be the natural
  next step.

## Notes

- `prepare_data.py` only needs to be re-run if the source Excel changes.
- District centroids and province populations both live in
  `utils/data_loader.py` — extend `DISTRICT_COORDS` or
  `PROVINCE_POPULATION` there if you get better source data.
- Pinned dependencies (`requirements.txt`) use exact versions so a future
  library update can't silently change behavior.
